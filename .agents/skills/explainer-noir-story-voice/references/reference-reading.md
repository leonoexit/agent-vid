## Repeated decisions underneath the surface

**A container is a claim about grouping.** A terminal says executable text/context; a colored top edge says role;
a nested inset says detail belonging to its parent. Before drawing a box, name what boundary it represents. Peer
objects use alignment; ownership uses containment; sequence uses order; dependency uses an explicit directed route.
Those relationships can coexist, but none follows automatically from a row of cards.

**Size follows the next inspection task.** Large typography suits an unresolved question or a demonstrated rule.
Reading a function body needs a dominant terminal; tracing two update requests needs room for sources and routes.
Do not reserve a top third for a title when its job is already done. A short contextual label can replace it.

**Whitespace is a separator with a job.** It creates room between argument and evidence, opens a travel corridor,
or lets a short statement dominate. Large empty bands left by copied scaffold coordinates have no such guarantee.
Describe what the gap separates. If nothing, redistribute useful content rather than add decorative assets.

**Color has a small amount of work.** The base dark field unifies; one active accent guides; stable peer accents
identify objects. Foreground/background opacity creates hierarchy but required text must remain legible. Depth,
rotation and blurred art are supporting signals, not core causal evidence.

**Density changes across the sequence.** In the original, 02→03→04→05 shifts argument, process+monitors, transport,
then a sparse statement. 09→10→11 moves definition/invocation, parallel roles, sequential work. A production trace
should change density when the viewer's task changes, while keeping the same example. Variety isn't a rotation
through a preset deck of layouts. No exact pattern count is implied by these observations.

## From static reference to time

Source supports the spatial choices above; animation is our design. Preserve a stable identity while moving from
context to detail or splitting ownership. For a module refactor, physically move existing method tiles from a shared
boundary to separate boundaries; reroute the same request to the newly responsible owner. Use local code edits and
output changes as evidence. A fade between two complete diagrams doesn't show what was retained or reassigned.
