# Build and review

From the repository root, activate `scripts/activate.sh`. Here `<skill>` is this skill's directory, `<pipeline>` is `.agents/skills/explainer-bento-programming-voice`, and `<project>` is a new project directory.

1. `python <skill>/scripts/new-project.py <project>` refuses an existing destination. Author `script.json`, the shot score, assets and `story.js`. The empty draft is deliberately not render-ready. Follow the runtime contract; do not add a new renderer.
2. Validate with `python <skill>/scripts/validate-script.py --project <project>`. Build the opening through its first explanatory payoff with accepted assets and real speech before completing the film. Include an interior handoff if it uses a different treatment. Review whether a first-time viewer can identify the topic, follow the operation and explain the result; use this to revise the script and staging, not just check that JS runs.
3. Vietnamese default: `python <pipeline>/scripts/tts.py --project <project> --engine vieneu --voice 'Hải Đăng'`. Honor explicit/stored preferences. English uses the installed Kokoro path. Then `python <pipeline>/scripts/sync-narration.py --project <project> --no-bgm`. Regenerate speech after narration edits and resync after screen-only script edits. Local word timestamps may be estimated; check important cue alignment against actual audio.
4. For technical testing only, sync accepts `--music-only --no-bgm` to produce silent estimated timings. Label these previews accurately. Do not use silent checks to claim narrated pacing.
5. Complete the video, then review normal-speed playback with sound, phone-scale legibility, longest held compositions, semantic commits and joins. Across every explanatory passage, check the before/during/after information order from [choreography](choreography.md): does context arrive in time, does evidence develop when the explanation needs it, and does the handoff retain what the next inference requires? Inspect within scenes as well as their openings. Correct premature reveals, late evidence and accumulated clutter; do not treat entrance effects alone as a fix. Use `visual-review.md` to record two separate judgments: editorial (orientation, causal clarity, development during the sentence, pacing) and technical (state, seeking, layout, decode). Cite actual intervals and revisions, including unresolved weaknesses. A list of short holds, ASR matches or passing layout tests is not an editorial pass. Sampled frames are useful for defects; they cannot prove tempo. If playback/listening is unavailable, disclose that limitation and leave that part unverified; continue the authorized work without silently certifying it or adding a user approval gate.
6. Run `hyperframes lint <project>` and `hyperframes check <project>`. Fix actual runtime, overflow and contrast problems; decorative bleed does not excuse cropped evidence. Then render: `hyperframes render <project> --quality high --fps 30 --output <project>/renders/<slug>-9x16.mp4`. Inspect metadata, full decode and critical intervals in the encoded file. Deliver the MP4 and useful source links.

Keep generated originals and prompt/reference provenance in the project. Covers are made on request; this scaffold does not export them automatically. Existing user projects and technical examples remain separate from a new production.
