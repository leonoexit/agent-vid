# Existing explainer production workflow

Use the installed sibling `explainer-bento-programming-voice` **technical utilities**, which are available in this workspace. Read its `references/script-schema.md` and relevant timing/script helpers when making a video. Do not import its Maple colors, frame, serif headings, hard shadows or card layout into the final Apple design. The Apple art direction in this skill controls styling.

This is a deliberate dependency on an established production path, not a new renderer. If those utilities are missing, report the missing dependency rather than silently starting an engine migration. No new video or conversion of historical projects is required merely to update this design skill.

1. From the repository root, activate `source scripts/activate.sh` for the shared TTS and HyperFrames runtime.
2. Create a fresh project using `python <pipeline>/scripts/new-project.py <project> --language vi --voice 'Hải Đăng'`. Here `<pipeline>` is the installed `explainer-bento-programming-voice` directory. This produces a **Bento technical scaffold**, not an Apple-ready result.
3. Write the worked example and phrase-to-picture storyboard. Replace the scaffold's `worked-trace-v1` marker with `storyFormat: "apple-action-v1"`, add the user's `audience`, and write the `story` brief (question/example/takeaway). Follow [narrative.md](narrative.md). Choose scenes from the visual actions; optional phase labels are flexible. The technical intro/scenes/outro containers do not require Bento's six-phase narrative. Author/replace the project's HTML/CSS/SVG visual layer in the Apple style, with `assets/apple-assets.css` as a material reference. Preserve timeline/audio hooks. Replace the actual element styling and geometry; appending a few color overrides to the Bento page does not complete the adaptation. Copy the font assets/licenses when used. Copy the native assets/helpers described in [toolkit.md](toolkit.md) for recurring operations; model-specific diagrams/actions and phrase cues remain in the project. Plan caption colors, camera focus and background roles using [engagement.md](engagement.md).
4. Validate with `python <apple-skill>/scripts/validate-script.py --project <project>`, where `<apple-skill>` is this skill directory. This wrapper retains the shared technical checks and applies Apple's flexible story contract; do not send `apple-action-v1` directly to Bento's narrative validator. Generate voice with `python <pipeline>/scripts/tts.py --project <project> --engine vieneu --voice 'Hải Đăng'`, then run `python <pipeline>/scripts/sync-narration.py --project <project> --no-bgm`. Honor stored voice/language preferences. Use offline mode only when models are cached.
5. Use the existing motion audit, `hyperframes lint <project>` and `hyperframes check <project>`; resolve relevant errors. Inspect the actual Apple scene composition, important state changes, caption readability and synchronization. Generic scaffold validation is not visual approval.
6. Export with `hyperframes render <project> --quality high --output <project>/renders/<slug>-9x16.mp4`. Check dimensions, duration, audio and full decode. After video QA, create and check its Facebook video cover using [cover.md](cover.md). Deliver the video, cover PNG/JPG and editable HTML, and report material review limitations.

The visual kit can be inspected directly as `assets/visual-kit.html`. It has no JS framework, animation engine, CDN or network asset dependency. It is a design reference, not a HyperFrames composition, so do not render it as a finished explainer or claim production parity with an archived demo.
