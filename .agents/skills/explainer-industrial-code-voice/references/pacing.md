# Continuous explanation, purposeful pauses

Retention is an editing goal, not a measured promise. Default narration uses Hải Đăng at native speed 1.0;
paragraph gap 0.2s, scene hold zero, sync lead 0.15s/tail 0.35s. Do not stack a paragraph break, scene tail and
explicit hold for the same reading task. Existing projects retain their explicit voice.json and script holds.

- Hook with the confusion the example resolves; show the example promptly, rather than a long title preamble.
- Use short connected clauses: instruction → change → meaning → next question. Simplify language to preserve
  beginner comprehension; do not compensate for dense sentences by adding long silence or rushing the voice.
- Schedule a transfer/write near the start of the explanatory phrase. Its arrival must precede the sentence that
  names the new state. Read the result while it stays on screen, then move directly to the next operation.
- Keep the same code and objects through the boundary; update the highlighted line or relevant state instead of
  replaying the entrance. Do not add meaningless motion to conceal a stalled explanation.
- For an optional prediction, 0.3–0.6s can be a starting point after the question, with the problem visible and the
  answer delayed. If unfamiliar code genuinely needs longer, shorten it or provide the requested reading time.
  Record the reason; this range is guidance, not a universal comprehension or retention threshold.

Review generated audio, not word-count estimates: include TTS pauses, paragraph gaps, scene spacing and holds.
Sync reports spacing outside voiced clips. Listen to boundaries and inspect action start/middle/end; a transfer
needs time to arrive and be seen. Cue it earlier before increasing hold. Do not trim speech to meet a target.
Compare retention only when actual viewing data exists; a faster version is not automatically clearer.
