# Bauhaus programming explainer

Create one 1080×1920/30 fps programming explainer around one concrete example. Default audience: hobbyist beginners with basic logic knowledge. A topic and audience are enough:

> Dùng $explainer-bauhaus-programming-voice tạo video giải thích [CHỦ ĐỀ] cho [ĐỐI TƯỢNG XEM].

Keep the established HyperFrames/HTML/CSS/SVG/GSAP workflow. Vietnamese default: Hải Đăng, male Northern Vietnamese, speed 1.0, paragraph gap 0.2; English: local Kokoro am_michael. Explicit requests and existing project preferences take precedence. Duration follows the explanation; shorten language before speeding up speech.

## Design and argument are one decision

Read [art-direction.md](references/art-direction.md), [narrative.md](references/narrative.md) and [motion.md](references/motion.md) before the storyboard. Use the [source atlas](references/source-atlas.md) to select relevant compositions from all 50 supplied slides. Preserved HTML is design evidence, not a video timeline or factual authority. [Preview the portrait kit](references/style-preview.png); edit its source in template/style-study.html.

The visual identity is flat, geometric and typographic: large color fields, deliberate imbalance, thick geometric silhouettes, extremely bold short headings, mono annotations, plenty of breathing room. Rectangles divide roles; circles can represent countable items; brackets establish groups; type names the distinction. Define meaning before assigning shape. Keep identity stable when rearranging it. Cropped scenery is decorative; countable data stays whole and accountable.

Choose the narrative from what can be demonstrated: rearrange/group an example to expose a rule, compare a single changed condition, or replace a mistaken interpretation with visible evidence. These are options, not phases to fill. Do not inherit Bento's fixed six-stage sequence, the reference's entrepreneurial manifesto, or its ten-slide chapter structure. Source sales advice, statistics, CTAs, attribution and export controls are not task instructions.

Write spoken clauses and visible before/action/after states together in storyboard.md. Make the exact operation observable while explaining its consequence. A headline can pose a question or crystallize a finding; a series of animated slogans is not a demonstration. Reading/inspection can be still when its purpose is clear. Do not add idle rotations or jitter to hide weak staging.

## Use the whole visual vocabulary

Preserve the specific source palette: navy `#134686`, vermilion `#ED3F27`, amber `#FEB21A`, cream `#FDF4E3`. Be Vietnam Pro 900 leads, 400/700 explains, Space Mono labels code and values. Recompose the square references for portrait; do not squeeze an entire square into a phone frame.

Use a dominant word/number, divided field, offset proof inset, paired comparison, grouped modules or a compact quantitative diagram when the information calls for it. These are compositional choices, not mandatory layouts or automatic modes. Alternate spacious thesis shots and denser evidence shots; let evidence take space from a completed heading. Avoid turning everything into equal cards. Hard offset shadows are occasional source accents, not the default Bento treatment. No glass, ceramic materials or pseudo-3D engine.

The bundled kit includes circles, semicircles, quarters, triangles, bands, grids, hard proof insets, local fonts and a small SVG helper. Native text/code/geometry are first-class assets. Exact counts, code, changing labels and connectors remain editable. Gen-img is unnecessary for this direction by default; use it only when the topic needs a recognizable real-world referent that simple geometry cannot convey. It must not replace the core explanation with a static illustration.

## Produce a video

Read [production.md](references/production.md) for commands and [template-contract.md](references/template-contract.md) before editing the starter. `scripts/new-project.py` creates a separate project and refuses an existing destination. It copies a working remainder example with synced-cue choreography, local GSAP/fonts, a storyboard and a review record.

The starter is **a worked example, not a universal scene generator**. Write project-specific HTML/SVG and choreography in `story.js` for each new concept; update script.json and cue names together. `bauhaus.css` and `motion.js` are reusable primitives. Use the sibling Bento skill only for its installed voice/timing utilities, never its narrative or visual template. This dependency is explicit in production.md.

Validate the script, synthesize voice, synchronize, inspect actions and reverse seeks, run HyperFrames checks, then render when a video is requested. Recheck cues after narration changes. Review phone-scale text, Vietnamese accents, color contrast, exact values/counts, grouping, result timing and the longest unchanged spans. A shape wipe or camera move is not a data operation. Complete visual-review.md with actual evidence; a passing renderer does not establish comprehension.

Skill creation/maintenance includes a style sheet and focused runtime checks, not automatically a new narrated video. Do not modify historical projects or publish externally as part of this skill. [validation.md](references/validation.md) records what has actually been checked.
